================================================================================
                           DEPENDENCY FLOW ANALYSIS
================================================================================

┌─────────────────────────────────────────────────────────────────────────────────┐
│                          CURRENT DEPENDENCIES                                  │
│  (Arrows show direction of dependency: A → B means A depends on B)            │
└─────────────────────────────────────────────────────────────────────────────────┘

PRESENTATION LAYER DEPENDENCIES:
MainWindow → TranscriptionHandler → TranscriptionController → AudioDataProvider
MainWindow → ConfigManager, AppStateManager, ThemeManager  [PROBLEMATIC]
TranscriptionHandler → ConfigManager  [PROBLEMATIC - UI accessing infrastructure]

APPLICATION LAYER DEPENDENCIES:
TranscriptionController → TranscriptionOrchestrator → TranscriptionEngine
TranscriptionController → AudioDataProvider → AudioCapture
BatchProcessor → TranscriptionEngine, DocumentWriter

DOMAIN LAYER DEPENDENCIES:
TranscriptionOrchestrator → AudioDataProvider, DocumentWriter  [PROBLEMATIC]
TranscriptionOrchestrator → OverlapResolver, LocalAgreementTracker
TranscriptionEngine → WhisperModel (external dependency)

INFRASTRUCTURE LAYER DEPENDENCIES:
AudioDataProvider → AudioCapture → SoundDevice
ConfigManager → JSON, File System
AppStateManager → File System
DocumentWriter → File System

================================================================================
                          CLEAN ARCHITECTURE TARGET
================================================================================

┌─────────────────────────────────────────────────────────────────────────────────┐
│                         PROPOSED CLEAN ARCHITECTURE                             │
└─────────────────────────────────────────────────────────────────────────────────┘

DOMAIN LAYER (Innermost - No Dependencies)
├── Entities: Word, TranscriptionSegment, TranscriptionConfig
├── Domain Services: TranscriptionService, AudioProcessingService
└── Repository Interfaces: ConfigRepository, AudioRepository, OutputRepository

APPLICATION LAYER (Use Cases)
├── TranscriptionController (orchestrates domain services)
├── BatchProcessor (bulk operations)
└── UI State Management

INFRASTRUCTURE LAYER (Outermost - Adapts to domain)
├── AudioDataProvider implements AudioRepository
├── JsonConfigRepository implements ConfigRepository
├── FileDocumentWriter implements OutputRepository
└── UI Framework adapters

DEPENDENCY INVERSION:
Domain defines interfaces ← Infrastructure implements them
Application orchestrates domain services
Presentation adapts to application services

================================================================================
                         REFACTORING PRIORITIES
================================================================================

PHASE 1 - INFRASTRUCTURE ABSTRACTION:
1. Extract repository interfaces in domain layer
2. Create infrastructure adapters
3. Implement dependency injection

PHASE 2 - BUSINESS LOGIC DECOMPOSITION:
1. Extract transcription algorithms (Strategy Pattern)
2. Separate state management from processing
3. Create domain services for complex operations

PHASE 3 - PRESENTATION CLEANUP:
1. Remove infrastructure dependencies from UI
2. Create view models for UI state
3. Implement MVP/MVVM pattern

PHASE 4 - CROSS-CUTTING CONCERNS:
1. Add logging abstraction
2. Implement error handling pipeline
3. Create centralized configuration management
